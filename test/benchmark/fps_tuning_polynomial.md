# FPS の多項式演算の調整

2026-10-18 JST に調査・測定した。対象は多項式 GCD・拡張 GCD・多項式逆元・Taylor shift・多点評価・補間。公開 API と、内部係数型以外の modint からの変換は維持する。

## 参考提出

取得時の上位 AC の一覧とソース SHA-256 は [fps_tuning_reference.json](results/fps_tuning_reference.json) にある。

| 問題・提出 | 取得時の時間 | 比較した手法 |
| --- | ---: | --- |
| [Inv of Polynomials #409589](https://judge.yosupo.jp/submission/409589) | 15 ms | 次数を指定する Half-GCD の jump。2 冪に合わせた分割、必要な行列成分のみの計算、変換のキャッシュ、fraction-free な小区間処理 |
| [Multipoint Evaluation #409516](https://judge.yosupo.jp/submission/409516) | 15 ms | 転置された積の木。8 個の木を SIMD の各レーンに置き、上位の通常の NTT と接続。積の木の変換を保存 |
| [Polynomial Interpolation #409545](https://judge.yosupo.jp/submission/409545) | 20 ms | 多点評価と木を共有。導関数の評価、一括逆数、線形結合を行う |
| [Polynomial Taylor Shift #409534](https://judge.yosupo.jp/submission/409534) | 10 ms | 階乗付き畳み込み。32 本の積の列、8×8 転置、専用の畳み込み。階乗の開始値には生成済みの表を使用 |

参考提出の値は公開ジャッジ上のプロセス全体の時間である。後述のローカル kernel 時間と直接比較しない。全体の最終比較は `fps_tuning` の資料にまとめる。

## 採用した変更

- 小区間の Half-GCD は、固定長の作業領域で係数を消去する。通常の商が 1 次なら、3 項の線形結合を AVX2 で計算する。途中の逆数計算を省き、最後に二つの行の尺度を一括して戻す。返す行列は従来の通常の互除法と同じになる。後続の商が参照しない低次係数は計算しない。
- 行列積の NTT を保存し、次の変換長が大きい場合は奇数側だけを追加する。積和の要素ごとの演算は 1 回の SIMD 処理にまとめる。
- GCD・拡張 GCD・多項式逆元は、必要な次数まで一度の `jump` で進める。分割点は 2 冪に合わせる。最終的に使う行列の上段だけを求め、定数となる結果は定数項だけから復元する。逆元の最後の余り計算も省く。
- Taylor shift の階乗・逆階乗は `components/fps_factorials.hpp` に分離する。32 本の積の列の区間積を求めて開始値を接続し、階乗と逆階乗を書き出す。参考実装の生成済み表は採用せず、任意の対応サイズに必要な値をその場で作る。非 AVX2・Mac ARM はスカラー処理を使う。

多点評価・補間の API・積の木・直接評価の分岐は変更していない。これらには共有 FPS・NTT の調整が別途反映される。

## 測定条件

WSL2 / Linux x86_64、Intel Core i7-13700F、GCC 15.2.0、CPU 2 に固定。`flock -x /tmp/cp-fps-tuning.lock` でコンパイル・テスト・他の測定と重ならないようにした。`-std=c++23 -O2 -DNDEBUG -march=native -ftrivial-auto-var-init=zero`、seed 294384。1 回ウォームアップ後、実行順を固定 seed でシャッフルして各 7 回測定する。

比較元は commit `fd41ae5df33960b93288ae98f9edac4e9fdb166f` の担当 7 ヘッダーである。共有 FPS・NTT などの依存先は 1 回取り込んで両方に使い、担当部分の効果を比べる。各試行は新しいプロセスとし、入力生成を除いた関数呼び出しと全出力のチェックサムを測る。出力・起動時間は測定しない。各入力で全試行のチェックサムが一致した。

## 試した案

探索中は各 5 回の測定を行った。これらは最終版より前の候補で、共有依存先のリビジョンも最終測定と異なる場合がある。全試行と記録時のハッシュは [experiments.json](results/fps_tuning_polynomial/experiments.json) に残した。

| 案 | 観測・判断 |
| --- | --- |
| 小区間の fraction-free 処理のみ | 50,000 係数の逆元 77.6 → 58.8 ms、GCD 56.7 → 40.6 ms。採用 |
| 行列の変換キャッシュ・積和融合 | 同じ規模の逆元 75.8 → 54.0 ms。採用 |
| 通常の 1 ステップごとに変換キャッシュも更新 | 外側の逆元処理を維持した候補では 54.0 → 64.7 ms と悪化。不採用。通常のステップではキャッシュを破棄する |
| 全次数を一度に処理する jump | 逆元 75.6 → 33.4 ms。採用 |
| 最後の行列の上段のみ計算 | 逆元 75.5 → 31.3 ms。採用 |
| SIMD で 64 点分の葉を一括構築 | 262,144 点の評価 68.33 → 67.94 ms、補間 99.88 → 98.05 ms。4,096 点の評価は 0.585 → 0.607 ms に悪化。安定した利得が小さく不採用 |
| Taylor shift の積の列を並列化 | 524,288 係数で 16.49 → 14.73 ms。採用 |

直接処理する次数の閾値も調べた。最終の低次係数の省略より前の候補で、単位 ms。64 と 128 の差は小さく、より大きい入力の逆元で 64 が良かったため 64 を維持する。

## 検証

既存の多項式 GCD テストでは、小区間の行列を通常の互除法と完全に照合し、GCD、Bézout 恒等式、逆元、疎な入力・共通因子・零多項式・異なる modint を確認した。新しい単体テストでは階乗・逆階乗を通常の剰余演算と照合し、Taylor shift を二重ループと比較した。NTT キャッシュの拡張、任意の次数までの jump、上段だけを求める結果も通常の互除法と照合した。

GCC の通常ビルド・`NDEBUG`、Clang の ASan/UBSan、AVX2 の分岐を無効にした一時コピーで成功した。記録は [check.log](results/fps_tuning_polynomial/check.log)。公式ケース・推移的な依存先・Mac の検証は全体の検証に含める。

```sh
flock -x /tmp/cp-fps-tuning.lock python3 test/benchmark/fps_tuning_polynomial.py --operations gcd,extended,inverse,taylor --sizes 4096,32768,50000 --trials 7 --output test/benchmark/results/fps_tuning_polynomial/final
```
