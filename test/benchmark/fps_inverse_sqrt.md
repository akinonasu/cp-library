# FPS 逆数・平方根の専用バックエンド

比較元は `ce81108`。2026-10-19（Asia/Tokyo）に、Linux x86_64 / AMD EPYC 9V74 / GCC 14.2.0 / CPU 2 で測定した。公開 FPS API と入力の保存を維持する。

参照した最速提出は、逆数 [409370](https://judge.yosupo.jp/submission/409370)、平方根 [409728](https://judge.yosupo.jp/submission/409728)。ソース SHA-256 はそれぞれ `611eaf933f4187e567c90214aa5fc93f6bce7d139a122f68d11b769deeaabe66`、`aa66b9de0c8361c9e9b46024c39231d50419f95335cfcce59cef7491e014dfbc`。

## 足りなかった実装

逆数は Newton 更新の計算式が同じでも、従来の SIMD NTT と共有の部分変換バックエンドでは、葉の積の融合・半分だけの逆変換・変換表の配置が異なっていた。`components/fps_inverse_blocked.hpp` から参照と同じ `blocked_poly::inverse` を呼び、最終更新の作業領域として入力の内部コピーを再利用する。入力の Montgomery 解除を省き、出力へ $R^2$ を掛ける。$R=2^{32}\bmod998244353$ とする。

次数が 2 冪を少し超えるとき、単純な移植では最後の少数項のため変換長が倍になり、131073 項で退行した。この場合は既存と同じ内積による末尾の補完を残す。

平方根は従来の多ブロック法から、最速提出の Newton 更新へ変更する。平方根とその負の逆数を同時に延長し、次数 8 の葉では通常の積より乗算数を減らす専用二乗を使う。逆変換の最上段と次の順変換を融合し、最後の更新は Karp–Markstein の分割で変換長を半分に抑える。共有バックエンドには半分入力の radix-8 最上段と正規化倍率の事前計算も取り込む。

平方根の入力も Montgomery 解除を省く。内部では $\sqrt{Rf}$ を計算し、出力に $2^{16}$ を掛けて元の平方根の Montgomery 表現とする。公開 API の先頭の零係数・定数項判定では入力を直接走査し、`pre`・`trim`・`erase` に伴う余分なコピーを除く。入力の不足部分は 0 として扱う。

## 測定

`-std=c++23 -O2 -DEVAL -DONLINE_JUDGE -ftrivial-auto-var-init=zero -march=haswell`、assert 有効。各版をビルドしてから排他ロック内で測定し、他のコンパイル・テストを並行実行しない。予備実行 1 回、seed 20261019 で順番を変えた 9 回の中央値。単位 ms。計算時間は確保・初期化を含み、入力生成と出力チェックサムを除く。全チェックサムを照合した。

| 項数 | 逆数・比較元 | 逆数・採用版 | 平方根・比較元 | 平方根・採用版 |
| ---: | ---: | ---: | ---: | ---: |
| 32768 | 0.550 | 0.458 | 0.704 | 0.484 |
| 131073 | 2.271 | 2.167 | 3.053 | 2.631 |
| 500000 | 9.254 | 7.512 | 12.040 | 7.518 |
| 524288 | 9.141 | 7.493 | 12.364 | 7.726 |

50 万項の計算は、逆数で約 18.8%、平方根で約 37.6% 短縮した。

この測定時点の入出力を含むプロセス全体は、逆数 15.817 → 14.598 ms、平方根 18.642 → 14.879 ms。参照原本はそれぞれ 10.773 / 10.807 ms だった。これは一括入出力の追加調整前のスナップショットであり、最終統合版の全体時間とは区別する。平方根には定数項が平方剰余である `max_random_01.in` を使う。`max_random_00.in` は根が存在せず、計算部分の比較に適さない。

全試行、入力・ドライバー・バイナリ・全ヘッダーのハッシュは [測定記録](results/fps_inverse_sqrt.json) にある。参照原本は変更せずコンパイルした。ローカルの実測であり、Library Checker 実機の最速獲得を示すものではない。

## 検証

通常・ASan/UBSan の専用単体テストで、0〜500000 項、2 冪と最後の分割の前後、入力長と次数の違い、内部剰余値の上限付近、先頭の零、入力の保存を確認した。既存 `fps_tuning_basic`、`fps_algorithms`、1025 項の `PlainMint` による逆数・平方根も確認した。

公式 checker では逆数 25 ケース、平方根 35 ケースが成功した。checker の引数は `input actual_output official_answer` とする。[検証記録](results/fps_inverse_sqrt_check.json) にソースとバイナリのハッシュを残した。

```sh
python3 test/benchmark/fps_inverse_sqrt.py --baseline ce81108 --output inverse_sqrt.json
```

通常の API からは実行時 AVX2 判定を経て利用し、Clang・macOS・ARM・AVX2 非対応 CPU では既存の実装へ戻る。
