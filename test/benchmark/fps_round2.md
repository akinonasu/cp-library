# FPS の追加高速化

2026-10-19 JST。比較元は `144ae32387675fa2a889ea3e8cd19b03ad5016bf`。前回の専用カーネル移植後に残った処理を見直した。公開 FPS API、入力を変更しない性質、一般の係数型・非 AVX2 環境の経路は維持する。

## 採用した変更

| 処理 | 残っていた費用と変更 | 参照提出 |
| --- | --- | --- |
| 逆数 | 最後に全係数へ掛けていた倍率を Newton 更新中に保つ。既存の積の係数へ逆倍率を吸収し、結果をそのまま Mint へ渡す | [409370](https://judge.yosupo.jp/submission/409370) |
| 指数 | Montgomery 入力の標準表現への変換と次数の乗算を 1 回にまとめる。巨大な更新本体のコード生成を崩さないよう専用関数へ分離 | [409662](https://judge.yosupo.jp/submission/409662) |
| 多項式除算 | const Mint の入力を正規化コピーしてから再読する処理を融合。商・剰余の結果生成を専用の 64 語バッチへまとめる | [409561](https://judge.yosupo.jp/submission/409561) |
| 合成 | Transform と専用の合成処理が別々に生成していた同じ根表を共有する | [409336](https://judge.yosupo.jp/submission/409336)・[409535](https://judge.yosupo.jp/submission/409535) |

逆数は同じバイナリの 99 回と追加 21 回を保存し、両最大入力の対応差を確認した。指数は変換単体では約 0.091 ms を短縮し、全体も独立した 2 組で改善方向だった。除算は複数の大きな商・剰余入力で再試行した。合成は根表だけの共有、作業領域縮小、padding 保持を同じ順序に混ぜて比較し、改善方向が揃った根表だけの共有を選んだ。効果量の小さい変更には計測変動があり、別セッションの中央値をつないで改善率を作らない。

詳細な倍率・範囲・採否は [逆数](fps_inverse_round2.md)、[指数](fps_exp_import.md)、[除算](fps_division_round2.md)、[合成](fps_composition_round2.md) を参照。今回の変更は専用の 4 ヘッダーに閉じ、共通の `fps_blocked.hpp`・入出力・作業領域の確保処理は変更していない。

## 同条件の全体比較

GCC 14.2、AMD EPYC 9V74、CPU 2 固定。全版を `-std=c++23 -O2 -DEVAL -DONLINE_JUDGE -ftrivial-auto-var-init=zero -march=haswell` でビルドする。公開入力の生成、確保・コピー、計算、結果生成、通常ファイルの入出力、起動・終了を含めて比較する。共有 flock でビルド・テストし、排他 flock で計時を分離する。

`fps_all_speed.py` の 21 試行による 16 問の比較を `results/fps_round2_all_speed.json` に保存する。各版 1 回の予備実行後に順序をシャッフルし、全出力を `checker input actual answer` の順で検証する。最速参照ソースは未編集の原本を使う。今回 API で取得し直した各問題の先頭 C++ 提出も、比較対象の 16 提出と一致した。順位取得の原票は [fps_round2_reference_heads.json](results/fps_round2_reference_heads.json) にある。

| 処理 | 比較元 ms | 統合版 ms | 最速原本 ms |
| --- | ---: | ---: | ---: |
| 積 | 15.361 | 15.466 | 11.810 |
| 逆数 | 13.086 | 12.889 | 11.133 |
| 対数 | 14.575 | 14.616 | 13.108 |
| 指数 | 17.080 | 16.987 | 15.323 |
| 冪 | 25.343 | 25.151 | 23.126 |
| 平方根 | 12.878 | 12.847 | 10.851 |
| 多項式除算 | 6.460 | 6.405 | 5.255 |
| 線形漸化式 | 55.424 | 55.475 | 57.719 |
| 合成（通常） | 2.870 | 2.814 | 2.811 |
| 合成（large） | 34.125 | 34.132 | 33.077 |
| 合成逆元（通常） | 2.609 | 2.600 | 2.532 |
| 合成逆元（large） | 31.042 | 30.772 | 30.074 |
| 多点評価 | 15.855 | 15.924 | 15.142 |
| 補間 | 20.206 | 20.237 | 19.317 |
| Taylor shift | 10.994 | 10.996 | 9.520 |
| 多項式逆元 | 15.763 | 15.665 | 14.981 |

逆数・指数・通常の合成は今回の統合比較でも改善方向だった。通常合成の原本との差は約 0.003 ms で、ほぼ同じ中央値である。large 合成は専用比較で 3 組とも改善方向だったが、この統合比較ではほぼ同じ時間になった。変更していない演算にも小さい差が出ており、根表の生成削減や乗算数の短縮を、そのまま全体時間の確定的な短縮量とは扱わない。

除算の `max_random_00` は変換を多く要する商・剰余ケースを代表しない。`v_random_01/02/03` と `n_max_00` の個別比較も行い、専用資料へ区別して記録する。小さい一つの差を、全入力での改善率として広げない。

同じ統合版・比較元・原本のバイナリを再コンパイルせず使った、重い除算入力の追加 21 試行は次の通り。列の値は全体時間の中央値である。

| 除算入力 | 比較元 ms | 統合版 ms | 最速原本 ms |
| --- | ---: | ---: | ---: |
| v_random_01 | 10.932 | 10.700 | 8.306 |
| v_random_02 | 13.996 | 13.264 | 11.912 |
| v_random_03 | 11.709 | 11.414 | 9.727 |
| n_max_00 | 13.212 | 12.725 | 10.286 |

対応する同じ反復の短縮中央値は 0.284 / 0.651 / 0.344 / 0.459 ms、勝数は 16 / 17 / 16 / 21（各 21 回）だった。中央値同士の差とは区別する。264 出力の checker と親原票に対する全バイナリ・ソースのハッシュ照合が成功した。[原票と再現コード](results/fps_round2_validation/division_heavy_recheck.json) に全試行と親記録との対応を残した。

この比較は指定した入力と環境でのローカル測定で、実際の judge の順位ではない。全関数で最速原本と同等になったとの主張もしない。変更していない関数の小さな時間差を今回の改善として数えない。

```sh
python3 test/benchmark/fps_all_speed.py \
  --baseline 144ae32387675fa2a889ea3e8cd19b03ad5016bf \
  --work /tmp/fps-round2-all-speed --trials 21 \
  --output /tmp/fps-round2-all-speed.json
```

## 採用しなかった候補

全段で 2 本の NTT を同時に進める [畳み込み](fps_convolution_pair.md)、平方根の出力バッチ、逆合成・射影の根表共有、[評価・補間・Taylor shift](fps_evaluation_round2.md) の境界コピー削減、[共通入出力](fps_boundary_round2.md) の候補も比較した。計算単体だけの短縮、入力による勝敗の逆転、全体の退行があるものは採用していない。これらの費用が不可避、または追加改善が不可能だと示す結果ではない。

## 最終の検証

`results/fps_round2_validation/selection.json` は比較元との推移的な依存差分から選んだ対象である。GCC 14・Clang 19 の各 25 ヘッダー・25 単体、GCC の native 単体 5 件の ASan/UBSan、Yosupo 22 ドライバーの全 596 入力が成功した。Yukicoder の 2 ドライバーは token がないためローカルでは skip し、対応する単体は確認した。

実依存 164 ファイルと plan fingerprint、公式検証 176 ファイル、文書生成対象 569 ファイルの前後ハッシュはそれぞれ一致した。生存中の Mint オブジェクトへの書き込み、入力末尾、読み取り専用入力、2 冪の前後、入力・出力の共有も各変更の専用テストで確認した。Sanitizer は `ASAN_OPTIONS=detect_leaks=0`・`UBSAN_OPTIONS=halt_on_error=1` で実行した。

文書 144 ライブラリと 123 judge source の生成、全 144 metadata と影響する 25 bundle のコンパイルに成功した。ローカルで Boost がない FPS 外の judge source の属性取得警告 1 件は原票に区別して記録し、全件の属性取得成功とは扱わない。生成 Markdown 本文に意図しない Liquid の開き記号がないことも確認した。最終の条件・結果・全ログは [result.json](results/fps_round2_validation/result.json)、[judge_audit.json](results/fps_round2_validation/judge_audit.json)、[docs_result.json](results/fps_round2_validation/docs_result.json) を参照する。
