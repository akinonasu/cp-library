# FPS の係数型と ACL modint

2026-10-22。実装の基準は `0870867`、ACL は `864245a00b00dd008d1abfdc239618fdb7d139da` です。ライブラリ本体は変更せず、現行 FPS の係数型を変更した場合の時間を測りました。

## 比較した実装

```cpp
using CustomFPS = FormalPowerSeries<mint>;
using ACLFPS = FormalPowerSeries<atcoder::modint998244353>;
```

この 2 種類は現在のライブラリで利用できます。`fps` は前者の別名です。後者の積・二乗・逆数・対数・指数・平方根・冪・級数除算・多項式除算は、入力を内部の Montgomery 表現へ変換して同じ高速処理を呼び、結果を ACL の型へ戻します。

したがって、以下は **公開する係数型を ACL にする場合の測定** です。内部の独自 modint を全て削除した実装の測定ではありません。NTT・ブロック演算・SIMD は Montgomery 表現や `mint::word`・内部ワードへのアクセスにも依存します。内部まで ACL の標準表現に統一するには、それらの実装を変更する必要があり、この測定からその場合の FPS 全体の時間は決められません。ACL の畳み込みを使う実装との比較も、アルゴリズムと SIMD の差まで含むため今回は行っていません。

## 基本演算：524,288 係数

Linux x86_64、AMD EPYC 9V74、GCC 14.2、CPU 2 固定。`-std=c++23 -O2 -march=haswell -DEVAL -DONLINE_JUDGE -ftrivial-auto-var-init=zero -Wall -Wextra -Werror` と通常 CI の constexpr 上限を使いました。ヘッダー内部の最適化指定も有効です。NDEBUG は指定していません。

各条件・各実装を 9 回、新しいプロセスで実行した中央値です。実行順は固定 seed で並べ替えました。入力生成・入出力・結果の検証は除き、演算中の確保と変換、根表の初回構築を含めています。単位は ms です。

| 演算 | 現行 mint | ACL 型を指定 | ACL / 現行 |
| --- | ---: | ---: | ---: |
| 積 | 5.217 | 8.156 | 1.563 倍 |
| 二乗 | 5.163 | 7.241 | 1.403 倍 |
| 逆数 | 7.263 | 8.722 | 1.201 倍 |
| 対数 | 9.345 | 10.730 | 1.148 倍 |
| 指数 | 11.719 | 13.241 | 1.130 倍 |
| 平方根 | 7.198 | 8.605 | 1.195 倍 |
| 冪 | 19.334 | 20.758 | 1.074 倍 |
| 級数除算 | 9.513 | 12.004 | 1.262 倍 |
| 多項式の商・余り | 7.138 | 8.917 | 1.249 倍 |

積・二乗の出力は 1,048,575 係数です。多項式除算の除数は 262,144 係数、冪の指数は 123456789 です。それ以外の入力・出力は 524,288 係数です。

この条件では、主な FPS 演算の時間は約 7〜56% 増えました。同じ高速な内部処理を使うため、主な追加分は入力・出力の表現変換と配列の確保・コピーです。同じ係数列を使っても、演算を呼ぶたびに係数型の変換が入ります。二乗は入力の変換を共有します。

## 線形時間の演算：524,288 係数

| 演算 | 現行 mint | ACL 型を指定 | ACL / 現行 |
| --- | ---: | ---: | ---: |
| 定数倍 | 0.607 | 1.002 | 1.650 倍 |
| 微分 | 0.495 | 1.133 | 2.287 倍 |
| 積分 | 0.723 | 1.640 | 2.267 倍 |
| 一点評価 | 0.079 | 2.174 | 27.537 倍 |

定数倍は 123456789 倍、一点評価の引数も 123456789 です。これらは短い演算のため、同じプロセスで `max(4,131072/n)` 回呼び、1 回あたりに換算しています。結果配列へのコンパイラのメモリバリアを各回に置き、不要な計算として消されることを防いでいます。積分の逆元表は初回構築分を含みますが、後続の呼び出しで再利用するため、そのコストも呼び出し回数で平均されます。

これらの ACL 型の処理は、現行 mint 向けの SIMD 経路を使いません。一点評価は現行版の AVX2 による複数列の計算に対し、ACL 型では通常の逐次 Horner 法になるため、大きな差があります。この差を modint の単一演算だけの速度差としては扱えません。

## 他のサイズと検証

1,024・32,768・131,073・524,288 係数について、13 演算・52 条件・計 936 サンプルを測定しました。全試行で出力長・余りの長さ・全係数からの checksum が一致しました。さらに、2・31・32・33・127・256・511・512・513・1,024・4,097・524,288 係数の 156 条件で、出力と余りの全係数を直接比較しました。

各サイズ・全試行の測定値、ソースと ACL ヘッダーの SHA256、コンパイラ・フラグ・乱数 seed・全係数比較の SHA256 は `results/fps_modint/measurements.json` と `measurements.csv` に保存しています。ローカルでの計算時間であり、judge 上の表示時間や全入力の性能を保証するものではありません。

既存の公開ヘッダーテストを `CP_FPS_HEADERS_ACL` 有効で GCC・Clang の両方で実行し、派生演算も確認しました。測定コードの ACL 型については Clang ASan・UBSan で 13 演算・4 サイズを実行し、GCC 版と全係数を比較しました。こちらの記録は `results/fps_modint/validation.json` に保存しています。ライブラリ本体と AtCoder のテストには変更を加えていません。

```sh
git clone https://github.com/atcoder/ac-library.git /tmp/ac-library
git -C /tmp/ac-library checkout 864245a00b00dd008d1abfdc239618fdb7d139da
python3 test/benchmark/fps_modint.py --acl /tmp/ac-library \
  --build-dir /tmp/fps-modint \
  --output /tmp/fps-modint/measurements.json
```

ACL の係数型との相互運用が必要な場合は `FormalPowerSeries<atcoder::modint998244353>` を利用できます。FPS の計算時間を優先する場合は、現在の `fps` を使い、他のコードとの境界で値を変換する方法が適しています。
