# 軽量 FPS の高速化

2026-10-21。`5e7f6ec` の軽量版を基準に、`light_fps` / `LightFormalPowerSeries<T>` の API を保って高速化しました。既存の大型 FPS と共有 `math/mint.hpp` は変更していません。[追加時の測定](fps_light.md) は履歴として残しています。

## 変更した処理

- NTT の下位 3 段を 8 要素ずつまとめ、スカラーの小さいバタフライを減らしました。根の表は前の段から並列に拡張し、逆根は順変換の表から求めます。
- 点ごとの乗算・逆変換の正規化も AVX2 で処理します。通常のバタフライ・要素積は Montgomery 乗算、小さい段の定数と正規化は Shoup 乗算です。根の全要素に Shoup の商の表を追加する方法は採用していません。
- 逆数・指数・平方根は、途中の逆数や変換結果を再利用します。指数は微分方程式から得る誤差を補正し、毎回の `log` と逆数の再計算を省きます。
- 平方根は既知の下位係数から長さ `k` の巡回平方の折り返しを復元し、上位誤差を求めます。長さ `2k` の平方を行う必要がなくなり、逆数更新の変換も再利用します。
- 級数除算は半分の精度の逆数から下位の商を求め、上位の誤差だけを補正します。対数もこの除算を使います。
- 大きい 2 冪の直後 1〜4 係数は、先に 2 冪まで求め、残りを定義式の漸化式で計算します。ごく短い末尾のための倍長変換を避けます。
- GCC / x86 のヘッダー内では `O3` を使い、最後に利用者側の設定へ戻します。別の modint 型は演算単位で内部の共有 `mint` へ変換します。

AVX2 は実行時に確認します。非対応 CPU のスカラー経路と、GCC / Clang 以外・x86 以外の分岐も残しています。基本演算の時間・作業空間・最大次数は従来と同じです。共有の根・整数逆元キャッシュを同時に拡張する並列呼び出しには対応しません。

大きい段を radix-4 で融合する候補、根ごとの Shoup の商を保持する候補、4,096 要素単位で再帰的に変換する候補も比較しました。今回の計測では大きい積・二乗に一貫した改善がなく、採用しませんでした。コアの `O3` 指定は同一実行内の比較で複数の演算が約 7〜10% 改善したため採用しました。[この比較の全サンプル](results/fps_light_speed/core_o3_screen.csv)・[条件と集計](results/fps_light_speed/core_o3_screen.json)・[実行スクリプト](results/fps_light_speed/core_o3_screen.py) を残しています。

## 計測条件

Linux x86_64 / AMD EPYC 9V74 の仮想環境、GCC 14.2、CPU 2 固定です。`-std=c++23 -O2 -DEVAL -DONLINE_JUDGE -ftrivial-auto-var-init=zero -march=haswell`、assert 有効、各 9 回の中央値です。ヘッダー内の限定した `O3` 指定も製品コードの一部として含めています。

「変更前」は `5e7f6ec` の軽量版、「変更後」は今回の軽量版、「既存高速版」は同じ基準コミットの大型 FPS です。同じ係数型・seed 731・入力生成コードを使い、3 版の実行順をシャッフルします。各サンプルを新しいプロセスで実行し、NTT を事前実行しません。入力生成・入出力・結果検証・プロセス起動は除き、演算中の確保と根の表の初期構築は含めます。計測とコンパイル・検証は 2 つの lock で排他実行しました。

積・二乗は両入力が `n` 係数で、出力は `2n-1` 係数です。他の基本演算は `n` 係数を要求し、多項式除算の除数は `n/2` 係数です。冪の指数は 123456789、平方根の先頭係数は 17² です。評価・補間の点は `0..n-1`、Taylor shift は 17、線形漸化式の項番号は 10^18 です。補間の値も直接生成し、計測前の多点評価を行いません。

各サンプルで結果の長さと全係数の checksum を照合し、商・余りも両方検証します。測定対象ヘッダー・入力生成コード・コンパイラ・フラグ・実行ファイルのハッシュを JSON に保存し、実行前後でソースが不変であることを確認します。公開 judge の表示時間との直接比較は行っていません。

既存高速版との所要時間の差は、524,288 係数の基本演算で 1.87〜3.65 倍まで縮まりました。追加演算は 32,768 の場合で 3.29〜10.83 倍の差が残ります。軽量版は共通 NTT・標準の積木や Bostan–Mori を共有し、既存高速版の大きい演算別カーネルや部分変換を取り込んでいません。ここに示した値はローカルの計算部分の測定です。

## 正しさ・互換性

- 基本演算の独立した愚直剰余演算との 455,785 チェックを GCC / Clang で通過しました。2 冪の前後、末尾 1〜4 係数、正の次数から始まる平方根、平方非剰余、指定精度、零・空入力、`LLONG_MAX` の冪指数などを含みます。
- NTT のスカラー / AVX2 一致と交差往復を 65,536 点まで検証し、根の表も独立した uint64 の剰余累乗と照合しました。Montgomery 表現の境界、非整列のポインタ、要素積の同一配列指定、短い末尾も検証しました。
- 基本演算・追加演算・NTT の 3 単体テストが Clang ASan/UBSan を通過しました。
- 公式生成器の全 314 入力を GCC / Clang で実行し、計 628 回すべて公式 checker を通過しました。積 53・逆数 25・対数 25・指数 26・冪 37・平方根 35・多項式除算 35・Taylor shift 38・多点評価 11・補間 9・線形漸化式 20 です。
- 実 ACL の `atcoder::modint998244353`、大型 FPS との両方の include 順序、4 ヘッダーの単独・二重 include、利用者マクロへの非依存を GCC / Clang で確認しました。
- 最大変換長 2^23 点も、順変換・逆変換後の全係数が入力と一致しました。

[単体・sanitizer・互換性・全公式ケースの検証記録](results/fps_light_speed/validation.json) と、[最大長 NTT・独立した 1,400 組の愚直積などの補足記録](results/fps_light_speed/ntt.json) にコマンドとハッシュを保存しています。大型 FPS と共有依存ヘッダーが基準コミットから変わっていないことも照合しました。

変更前の単体テストと、追加時の検証結果のハッシュも [比較証跡](results/fps_light_speed/baseline_proof.json) として保持しています。[最終監査](results/fps_light_speed/audit.json) は、計測・検証対象のソースの一致と、全サンプルからの集計の再計算を記録しています。

```sh

python3 test/benchmark/fps_light_speed.py --baseline 5e7f6ec --suite algorithms --sizes 1024 32768 --trials 9
python3 test/benchmark/fps_light_speed_check.py --problems /path/to/library-checker-problems --acl /path/to/ac-library --cxx g++ clang++ --sanitize-cxx clang++
python3 test/benchmark/fps_light_bundle.py --bundle /path/to/oj-bundle --output test/benchmark/results/fps_light_speed/bundle.json
g++ -std=c++23 -O2 -I . test/benchmark/fps_light_ntt_check.cpp -o /tmp/fps-light-ntt-check
/tmp/fps-light-ntt-check
```

`--baseline-tree` を指定しなければ、比較スクリプトは基準コミットを `git archive` で一時ディレクトリへ展開します。基準版の依存ヘッダーのハッシュをコミットと照合するため、変更後のコードを変更前として測ることはありません。CPU 2 が使用できない環境では `--cpu` を変更してください。
