## 実行経路と区間

密グラフ 4 ケースは頂点数 707・辺数 499142、全頂点の入次数・出次数が 706、辺の始点順に整列した完全有向グラフです。出辺を持つ行数は 707 のため `c075fb7` の先読み分岐は実行されません。2 版の密グラフでの論理差は、active 行数の集計と分岐です。先読み本体のランダムアクセスで 0.28ms 増えた、という説明は成立しません。

`max_dense_random_01` は重み 4620～999999495、全 707 頂点に到達し、距離 9127562・復元経路 8 辺です。native 区間ドライバは parse 3.755→3.707ms、build 1.330→1.360ms、solve 0.177→0.178ms でした。構築の約 0.030ms の増加だけで、前回実提出の約 0.282ms の増加を説明できません。

`max_sparse_random_01` は active 行数 216239、最大出次数 11、始点順はランダム、到達頂点数 199729、経路 14 辺です。構築は native 3.111→2.242ms、generic 3.186→2.353ms で、先読みの短縮が維持されています。実提出の変化率の bootstrap 95% 区間は native -7.19%～-0.96%、generic -7.74%～-1.67% でした。

user/system CPU 時間はサンプル単位では約 3ms の刻みで配分が大きく揺れます。0ms の区間もあり、0.1～0.3ms の差の原因を user と system の配分から断定していません。CPU・キャッシュ・ホスト状態を完全には観測できていないため、根本原因が一つに特定できたとはみなしません。

凍結ソースの原文 hash は各 `environment.json`、原文を参照インクルードに変換した保存ソースの再照合結果は `summary.json` にあります。Git revision・runner・hash から再生成できるため、重複ヘッダーは保存していません。`verification.json` には診断直後の凍結ソースを含む保存ファイルの hash を記録しています。再実行すると同じ保存先に凍結ソースを再生成します。
