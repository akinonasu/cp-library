# リファクタリングの検証

2026-10-21。比較元は `8b0a061430ea8355fa7b19cf39cda2a585644aba`。
公開 API・計算量・数値演算の順序を維持し、返却時のコピーと重複した処理を整理した。

## コピーの削減

FPS の多項式 `+`・`-` と `<<`・`>>` は、複合代入の参照を返さず、ローカル変数を返す。
NRVO が使われない場合も vector のバッファを移動でき、係数の移動コンストラクタを必要としない。
行列の値渡し演算子5種も、引数を直接返してバッファを引き継ぐ。

| 検証 | 修正後の条件 |
| --- | --- |
| 同じ長さの FPS の加減算 | コピー追跡型で係数のコピーは入力の複製に必要な `n` 回だけ |
| FPS の全消去シフト | 同上。返却時に `n` 回を追加しない |
| 行列の rvalue 加減算・左右のスカラー乗算・除算 | 戻り値の `data()` が元のバッファと一致 |

`test/unit/fps.cpp` と `test/unit/matrix.cpp` に回帰テストを追加した。
GCC 15.2.0、`-std=c++23 -O2 -Wall -Wextra -DDEBUG=1` で、変更前のヘッダーもコンパイルできるが、
それぞれ係数コピー数・バッファ引継ぎの検査で失敗することを確認した。
通常の成功確認は GCC・Clang の対象ユニットテストで行う。

## 共通化の生成コード

Linux x86_64、GCC 15.2.0。`-std=c++23 -O2` を共通とし、`-march=native` と `-DNDEBUG` の有無をそれぞれ比較した。
データ構造の比較用ディレクトリ名は `-ffile-prefix-map` で揃えた。

動的な木の子ノード更新では、再帰結果を直接代入する。C++17 以降は代入の右辺を先に評価するため、再帰中に vector が再確保されても、その後で左辺のノードを参照できる。

- Dynamic Lazy Segtree、Dynamic Li Chao Tree、Sortable Segtree の9操作を呼ぶ比較用 TU では、`-DNDEBUG` の generic/native 両方で変更前後のオブジェクトファイルがバイト単位で一致した。
- Sortable Segtree の `locate` は generic で自動 inline されなかったため、`[[gnu::always_inline]]` を付けて元と同じ探索を保った。
- assert 有効時の正常系にも追加の呼出や走査はない。assert 失敗時の行番号・関数情報と、失敗処理の分離・配置には差がある。
- 二部マッチングの被覆・独立集合・左右 Hall witness の頂点抽出は全4条件で自動 inline され、呼出数は増えなかった。レジスタ割当や例外経路には差があるため、機械語全体の一致とはしていない。

この確認は記載した型・操作の生成コードに対するもので、実行時間の短縮率は測っていない。

## 採用しなかった共通化

Bitwise Zeta と Walsh–Hadamard の2段融合・1024要素単位の走査を、共通のコールバック関数へまとめる案も試した。
演算順序は維持できたが、GCC の生成コードが変わり、遅くなるケースがあったため元の実装を維持した。

WSL2 / Linux x86_64、Intel Core i7-13700F、GCC 15.2.0、CPU 0 固定。
`-std=c++23 -O2 -march=native -ftrivial-auto-var-init=zero`、assert 有効。
`bitwise_transforms.cpp` の比較元を上記 revision のヘッダーに置き換え、mint・uint64・double の5変換を長さ `2^6`・`2^10`・`2^18`・`2^20` で各15標本測定した。
入力 seed、反復回数、交互の測定順、計測外の全要素一致確認は同ファイルの方式を使った。他のテスト・コンパイルは同時実行していない。

| double の部分集合ゼータ変換 | 変更前の中央値 ms | 不採用案の中央値 ms |
| --- | ---: | ---: |
| `n = 2^18` | 0.600938 | 0.700289 |
| `n = 2^20` | 2.677747 | 3.020440 |

AtCoder・Library Checker 上の実行時間は今回測定していない。

## 動作確認

変更したヘッダーと推移的な利用先だけを対象にした。

- GCC 15.2.0・Clang 21.1.8: 27ヘッダーの単独 include、37ユニットテストが成功。
- Clang の ASan / UBSan: 同じ37ユニットテストが成功。
- 27ヘッダーの bundle: GCC・Clang の `-Wall -Wextra -Werror -fsyntax-only` が成功。
- 44個の judge 提出コード: GCC・Clang で成功。AtCoder・yukicoder は公開サンプルを使用した。

二項係数 prefix sum の2提出コードは、最初は yukicoder 2206 の認証が必要なデータを取得できず未実行だった。
公開サンプル1件を取得し、その2本だけを再実行して成功した。他の42本は再実行していない。
Sortable Segtree の inline 属性を更新した後の GCC 確認も、そのヘッダーとユニットテストだけを追加実行した。
