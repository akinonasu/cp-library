# 汎用 Segtree Beats

`data_structure/generic_segtree_beats.hpp` に `GenericSegtreeBeats<S,op,e,F,mapping,composition,id>` を追加しました。既存の `data_structure/segtree_beats.hpp` と `SegtreeBeats<T,Sum>` の API・実装は変更していません。

## 実装

- 集約値と更新を別の型にし、結合・単位元・作用・合成をコンパイル時に指定する。
- `mapping(f,S&)` は成功を bool で返す。失敗した区間は合成済みの更新を子へ伝え、再集約する。失敗時に集約値を書き換えていても処理できる。
- 遅延伝播先でさらに失敗した場合も再帰的に処理する。葉での成功を必須とする。
- 通常の区間分解・集約・境界探索は反復処理。失敗時の展開だけ再帰する。
- dirty フラグで未伝播の更新を管理する。タグの等値比較、不要な単位更新の作用・合成、伝播後の単位タグへの書き戻しを省く。
- 非可換な集約、`max_right`・`min_left`、空列、コピー、再構築、デフォルト構築できない集約値・タグに対応。

## 参考

[ABC256 Ex 公式解説](https://atcoder.jp/contests/abc256/editorial/4113) の、作用が失敗したら子へ降りるという構成を確認しました。[hitonanode の ACL ベースの実装](https://hitonanode.github.io/cplib-cpp/segmenttree/acl_beats.hpp.html) も確認しています。参照側は `S.fail` で失敗を表し、遅延セグメント木の継承・仮想関数で作用を拡張しています。本実装は独立したクラスで、任意の `S` に対して bool を返す作用を使います。

Library Checker の Range Chmin Chmax Add Range Sum の AC 一覧を実行時間順に取得しました。時刻・一覧・ソース SHA-256 は `results/generic_beats_reference.json` にあります。

| --- | ---: | --- |
| [#204482](https://judge.yosupo.jp/submission/204482) | 225 ms | 先頭の C++ AC。汎用の Beats の木と、chmin/chmax 用のノード型を分離。最大・最小の第 2 値と個数で作用の成功を判定し、反復処理で区間を分解 |
| [#272331](https://judge.yosupo.jp/submission/272331)、[#272330](https://judge.yosupo.jp/submission/272330) | 231 / 236 ms | 同系列の OY の木と chmin/chmax のノード型を使用。入出力部分が異なる |

## 測定条件

WSL2 / Linux x86_64、Intel Core i7-13700F、GCC 15.2.0。CPU 2 に固定し、1 回のウォームアップ後に各 7 回を測定します。実行順は固定 seed でシャッフルし、中央値を取ります。実行ファイルは Linux 側の `/tmp` に置き、他のテスト・コンパイルとは同時実行しません。

- generic: `-std=c++2b -O2 -DNDEBUG`
- native: 上記に `-march=native -ftrivial-auto-var-init=zero` を追加

構築時間と操作時間を分けて測ります。汎用版の構築は元の整数列から `S` の葉を作る処理と、その一時配列の破棄を含めます。操作時間は全クエリのチェックサムを含みます。入力生成、入出力、最後の木の破棄は測定外です。全方式・全試行で答えのチェックサムを照合します。

| 操作列 | 要素数 / 操作数 | 内容・比較対象 |
| --- | ---: | --- |
| mixed | 200,000 / 200,000 | ランダム区間の chmin・chmax・加算・和。汎用版、既存の専用版、#204482 |
| short | 200,000 / 200,000 | 同じ操作で区間長を最大 64 にする |
| assign | 200,000 / 200,000 | 代入も含める。汎用版と既存の専用版 |
| uniform | 200,000 / 200,000 | 同値から始め、更新は全区間、和はランダム区間 |
| division_mixed | 500,000 / 100,000 | ランダム区間の除算・代入・和。汎用版と均一区間のみ直接更新する再帰版 |
| division_short | 500,000 / 100,000 | 同じ操作で区間長を最大 64 にする |
| division_decay | 500,000 / 100,000 | 代入なしの除算・和 |

除算の比較元は公式解説の均一区間判定を使い、構築・更新・伝播・和の取得を再帰で行います。均一区間の和は交差する長さから直接求めます。汎用版は最小値と最大値の商が一致すれば、元の値が異なる区間でも成功します。比較には木の処理方式と成功条件の両方の違いを含みます。

ソース、環境、フラグ、seed、全試行、チェックサムは `results/generic_beats_generic/results.json`・`results/generic_beats_native/results.json` に保存します。AtCoder 実機の測定ではありません。

## 検証

- 除算・代入・和、32 bit AND/OR・和・最小・最大、chmin/chmax・加算・代入を愚直な配列と照合。chmin/chmax では既存の専用版とも照合。
- 非可換な文字列の結合と更新、非可換なタグの合成、左右の境界探索、1 点・空区間・空列・非 2 冪長・コピー・移動後の再構築を確認。
- 親では成功し子では失敗する作用、伝播中の再帰展開、失敗時に集約値を壊す作用を検証。タグの等値比較とデフォルト構築を持たない型でも確認。
- 500,000 要素で除算を繰り返すケースと、大きい除数・合成時の飽和を確認。
- GCC 13・15、Clang、release の `-DNDEBUG -Werror`、ASan/UBSan、単独・結合ヘッダーのコンパイルを確認。
- Library Checker の公式 33 ケースを GCC・Clang で確認。
- ABC256 Ex の公式公開サンプル 2 件、500 操作のランダム入力 30 件、ドキュメントのコード例を確認。AtCoder への提出や非公開ケースの検証は行っていません。記録は `results/generic_beats_samples.json`、再現は `generic_beats_samples.py`。
- API 表・計算量表記・公開ページの生成を確認。

この操作列では、chmin/chmax 用の専用版が速い結果でした。均一区間のクエリを区間長から直接計算できること、操作ごとに必要な集約値だけを取り出せること、コンパクトなノード配置が有利です。汎用版は `S`・`F` の処理と任意の `op` による集約を行うため、同じ性能にはなりません。

除算でも均一区間用の再帰版の方が速い結果でした。汎用版は最小値・最大値の商で打ち切れる一方、タグの合成・反復処理・集約値のコピーの負担があります。汎用版全般での最速性や、他環境での速度は主張しません。
